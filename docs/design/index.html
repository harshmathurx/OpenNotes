Decision Log

Arguments we actually had. The ones that hurt. Raw, unpolished.

#1: Toolbar vs. No Toolbar

Debated for: 3 hours across 2 sessions · Resolution: 70/30 split

Should we have a visible formatting toolbar like Notion/Google Docs, or go full iA Writer with tools summoned on demand?

WON: No visible toolbar
Tools appear only on slash menu and Cmd+K. The page stays clean. Primary archetype says "I don't want to think about the editor."
LOST: Visible formatting toolbar
New users discover features faster. Notion set the standard. But: every visible chrome element competes against the writing surface.
Risk we accepted: New users won't discover formatting features. We're betting that what they don't discover, they don't need. If user testing shows confusion, we'll add a contextual hint on slash.

#2: No Signup Ever vs. Optional Account

Debated for: 2 hours · Resolution: Unanimous after user research

Should we have an optional account for cross-device preferences? Product people wanted growth loops. Design and engineering pushed back.

WON: No signup. No email. No account. Period.
Files live in user's own storage. We never hold data. Radical trust is the differentiator. 6/8 users interviewed said they'd trust a tool more if it didn't ask for anything.
LOST: Optional account for sync preferences
Would enable cross-device settings sync and give us a growth channel. But: any account creates the perception that we're holding something. Breaks the core promise.

#3: Single File at a Time vs. Tabs

Debated for: 90 minutes · Resolution: Close (55/45)

Multiple files open simultaneously like a code editor, or single file like Notion? This was the closest call.

WON: Single active file (like Notion)
One note at a time = one thought at a time. Tabs encourage context switching, which breaks flow. Cmd+K for rapid switching is the compromise.
LOST: Multiple tabs (like VS Code)
Power users want to reference one note while writing another. This was the single most requested feature from Obsidian users during research.
Revisit at > 1000 DAU: If power users consistently request tabs and we have evidence it doesn't degrade the writing experience for primary archetype, we'll add them.

Risk Register

What kills the product if wrong. No hedging. These are the assumptions that keep us up at night.

The Focused Writer archetype is wrong about toolbar tolerance CRITICAL

If users actually want visible formatting tools (like Notion's slash menu or Google Docs' toolbar), our "no visible chrome" bet creates confusion, not calm. Signal: > 20% of users asking "how do I make text bold?" in feedback. Fallback: Add contextual formatting bar on text selection — keep it hidden until needed.

Green (#16a34a) reduces trust HIGH

Users associate blue with tech credibility and green with finance/gaming. If A/B testing shows higher bounce on green vs. blue landing page, we have a brand perception problem. Signal: User testing comments about the color feeling "wrong" or "not serious." Fallback: Shift to muted sage green or deep navy blue.

Data ownership matters less than we think HIGH

Our core differentiator is "files in your own storage." If most users don't actually care where their files live (they just want sync to work), we're competing on a weaker axis. 6/8 interviewees cared, but that's a small sample. Signal: Low engagement with storage provider picker, high bounce at connection step. Fallback: Make local storage the default path (no setup required) and treat GitHub/Dropbox as power-user features.

Markdown syntax remains a blocker despite live rendering MEDIUM

Live rendering (type # Header -> see header) is our answer to markdown anxiety. But some users may still find the raw syntax jarring. Signal: Slash menu usage > 60% of formatting actions (indicating users avoid raw syntax). Fallback: Consider WYSIWYG mode as toggle — rendered-only view with formatting buttons. Tradeoff: adds UI chrome, violates principle #1.

Offline-first architecture is harder than estimated MEDIUM

Conflict resolution is the hard part, not sync. If our conflict modal frustrates users (confusing options, data loss), trust erodes fast. Signal: > 5% of sync operations result in unresolved conflicts. Fallback: Auto-merge with granular version history (like Google Docs). Tradeoff: significantly more complex, may delay Phase 2.

Design Principles

The decision filter. When in doubt, these resolve conflicts. Each one makes an explicit tradeoff.

01

The editor is the product

Every feature competes for pixels against the text area. The text area always wins.

Tradeoff: Rich features lose to focused writing.
Source: Primary archetype — "I don't want to think about the editor."
Test: Squint at the screen. If text area isn't >60% of visual weight, we failed.
02

Data belongs to the user

Files live in storage the user already controls. We never hold data on our servers.

Tradeoff: No "sign in with OpenNotes." No managed cloud. No collaboration.
Source: 6/8 interviewees — "Ownership anxiety trumps latency anxiety."
Test: Can you take your files and leave in 30 seconds with zero data loss?
03

Sync is invisible until it needs attention

Sync happens in the background. Green when fine. Amber when pending. Present when at risk.

Tradeoff: No per-file badges, no sync history view. We choose calm.
Source: "Users only think about sync when it fails."
Test: Does the user notice sync at all during a normal writing session?
04

Markdown rendered live, syntax transparent

Type # Header and see a header. The rendered result is the default view.

Tradeoff: WYSIWYG vs source mode. We show rendered by default.
Source: Research — "Markdown is a power user's comfort language, a regular user's blocker."
Test: Can a non-technical user format text without knowing markdown? (slash menu)
05

Files are flat by default, organized by name

No workspaces. No drag-and-drop folders. Grouping via / in filenames.

Tradeoff: Deep hierarchies help large collections. We choose simplicity.
Source: "Users think 'I want ideas.md' — not 'navigate to folder then ideas.'"
Test: Can you find any file in < 3 keystrokes via Cmd+K?
06

Every keystroke is safe

Content saves to IndexedDB on every change. Close tab, crash browser, lose power — words are there.

Tradeoff: No "discard changes" flow. Every edit is committed. Undo is your discard.
Source: The Focused Writer's core fear — losing work mid-flow.
Test: Kill the browser process mid-sentence. Reopen. Same content, same cursor.
07

Beautiful by subtraction, not addition

Polish means removing. Everything that can be hidden is hidden by default or one click away.

Tradeoff: Discoverability loses to clarity. Hidden features might be missed.
Source: "The first 3 seconds determine the writing session."
Test: Count UI elements visible on load. We're trying to get below 12.
08

Open by default, portable forever

Every file is a .md file. No proprietary format. No export step. Already portable.

Tradeoff: No databases, kanban boards, computed tables. Those lock you in.
Source: Data portability — portable data is owned data.
Test: Open a file in VS Code. Same content, fully functional. If not, we added cruft.

Voice & Tone

How OpenNotes speaks. Quiet, direct, confident, clean. The difference is what the user feels.

The Four Voice Adjectives

Q Quiet

Interface doesn't shout. Labels are short. Errors are calm. Success doesn't celebrate.

D Direct

No fluff. No "please." No "oops!" Say what happened and what to do.

C Confident

The product knows what it is. No hedging. No "We recommend..." Just factual.

C Clean

Every word earns its place. If a sentence can be three words, it's three words.

Real Product Copy

Sync status
"Synced" — One word. Calm. The user isn't thinking about sync. Neither is the interface.
Conflict resolution
"This file changed on both devices. Pick which version to keep." — Explains what happened. Gives clear action. Doesn't blame the user.
Empty sidebar
"No files yet" — Honest + inviting. Not a void. Not a celebration.
Infantilizing (rejected)
"Oops! Something went wrong." — The product didn't trip. An error occurred.
Performative politeness (rejected)
"Congratulations! You've created your first file." — Creating a file is not an achievement.
Celebrating the routine (rejected)
"Your changes have been saved successfully!" — "Saved" is enough. No exclamation points for routine operations.

Ship & QA

Taste references, bravery budget, accessibility, and the quality bar.

Taste References

N Notion

Taking: Clean white aesthetic, Cmd+K palette, calm composability.

Not taking: Block-based editor, proprietary format, managed cloud.

L Linear

Taking: Keyboard-first, dark mode, sync as background, green accents.

Not taking: Issue tracking complexity, list-heavy UI.

O Obsidian

Taking: Wikilinks, local-first, markdown purity, file ownership.

Not taking: Plugin complexity, technical aesthetic.

i iA Writer

Taking: Focus mode, monospace writing, one-thing-well philosophy.

Not taking: macOS only, no wikilinks, paid.

Bravery Budget

1No toolbar. Just the editor.

Tools appear only on demand. Risk: new users won't discover features. Reward: focused writers stay in flow.

2No signup. No email. No account.

Risk: no growth loop, no email capture. Reward: radical trust becomes the differentiator.

3Green as the brand color. Not blue. Not gray.

Risk: could feel "off" to users expecting blue = tech. Reward: any screenshot is instantly recognizable as OpenNotes.

Accessibility Checklist

  • ✓ Every text-background combination meets AA contrast (verified at multiple font sizes)
  • ✓ Keyboard navigation: every interactive element reachable via Tab
  • ✓ Screen reader: sidebar announces as navigation, sync status as aria-live
  • ✓ Focus management: modals trap focus, return focus to trigger on close
  • ✓ Motion: all animations respect prefers-reduced-motion
  • ✓ Touch targets: minimum 44×44px on all interactive elements
  • ✓ Color: never the sole state indicator (sync, wikilinks, validation have icons + text)
  • ✓ 200% zoom: content reflows, nothing hidden or truncated

Error State Matrix

State What User Sees Recovery
Offline + unsaved Amber dot, "{n} unsaved" Auto-retry when online
Sync conflict Modal: both versions side by side Pick resolution (keep mine/theirs/merge)
Broken wikilink Red underline, tooltip "Not found" Click to create new file or fix link
Empty editor Blinking cursor on line 1 Start typing
First run Empty state with CTA Click "Create first file"

Not-Candidates-Ever

  • Collaboration / multi-user editing — requires server, violates data ownership principle
  • Non-markdown file formats — violates portability principle
  • AI features that read user content — violates privacy. (Client-side AI may be reconsidered if it runs locally.)
  • Subscription pricing — user owns storage, not us
